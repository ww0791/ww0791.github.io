基于 Spring AI Alibaba 手撸一个企业研发助手 Agent（架构解析 + 全量代码）

Created2026-05-07|Updated2026-05-07|AI工程
|Word Count:3.4k|Reading Time:15mins|Post Views:

企业里那种”一句话帮我改代码 / 查工单 / 部署服务”的研发助手 Agent（内部常被起名为小龙虾、摩卡、鲁班…）底层到底怎么搭？本文把组件模型拆开讲清楚，再用 Spring AI Alibaba 从零手撸一个能跑的最小可用版，代码直接复制就能起。

目录导览

  • 第 1-3 章：架构解析。研发助手 Agent 的组件模型、Spring AI Alibaba 怎么对应上去、关键抽象（ChatClient / Advisor / Function / Memory / RAG）
  • 第 4-9 章：手撸实现。从 Spring Boot 工程初始化、接入大模型、注册工具、接 RAG、接 Memory、SSE 流式输出、多 Agent 协作，到 Docker 部署
  • 第 10 章：生产化要注意的坑

1. 研发助手 Agent 到底在做什么

表面看：工程师在 IDE 侧边栏对话框里问一句”帮我看看昨天那个超时的接口在哪”，助手就能：

  1. 理解意图 → “查询代码 + 看历史告警”
  2. 调工具 → git log 找昨天提交 + 查 Prometheus 拉告警
  3. 检索上下文 → 从代码库向量检索定位到具体类
  4. 生成答复 → 带着源码片段、告警截图、修复建议返回

拆开看，是一个**”意图路由 + 工具调用 + 检索增强 + 多轮记忆 + 流式输出”** 的大循环。

2. 为什么是 Spring AI Alibaba 不是裸 OpenAI SDK

Spring AI Alibaba 是阿里团队基于 Spring AI 做的扩展，核心好处：

  • 原生支持通义千问 / DashScope 系列国产模型（不用翻墙 / 不用代理）
  • 保持 Spring AI 的抽象：ChatClient、Advisor、ChatMemory、VectorStore、Function 通用不变，以后想切 OpenAI 只改一行依赖
  • 提供 nl2sql、graph、jmanus 等”Agent 级”扩展包
  • 和 Spring Boot / Spring Cloud 生态无缝衔接（自动装配、Actuator、配置中心）

对于企业 Java 后端团队，用 Spring AI Alibaba 省去自己造一层”AI 中间件”的成本。

3. 核心抽象一张表

抽象 作用 类比
ChatModel 最底层，直接 call(Prompt) 调模型 JDBC Driver
ChatClient 高层门面，链式 API 组装 prompt、插 Advisor、绑 Function MyBatis
Advisor 拦截器链，在调用前后做横切（日志、脱敏、RAG 注入） Spring AOP
Function（工具） 让模型调用 Java 方法，带 JSON Schema 描述 RPC 接口
ChatMemory 多轮对话记忆存储 Session 存储
VectorStore 向量库抽象，存取 embedding JPA Repository
EmbeddingModel 把文本转 embedding 的模型 Hash 函数
DocumentReader 文档加载器（PDF/MD/代码） BufferedReader
DocumentTransformer 文档切分、清洗 Stream.map

一个完整的 Agent = ChatClient + 若干 Advisor + 若干 Function + Memory + RAG。

框架流程：

  1. 把所有 @Bean Function 转成 OpenAI/DashScope 支持的 tools schema
  2. 模型返回 function_call 时，反射调用对应 Bean
  3. 把调用结果作为 role: tool 消息追加到 history，再次请求模型拿最终文本

你不用写任何解析代码，Spring AI Alibaba 自动完成 Tool-Use 循环（默认最多 5 轮，可配置）。

7.3 查询时用 QuestionAnswerAdvisor 自动注入检索结果

QuestionAnswerAdvisor 的工作：

  1. 拦截每次请求，把 user question 作为 query 去向量库检索 top-5 文档
  2. 把检索结果拼进 prompt（以”Context:”小节的形式）
  3. 再交给 LLM 生成

你的业务代码不用改，Advisor 自动完成 RAG 注入。

10. 多 Agent 协作：给 Agent 配”助手的助手”

复杂任务单靠一个 ChatClient 不够——比如”分析下这个报错并自动修 PR”需要：

  1. Diagnose Agent：看日志找原因
  2. Code Agent：改代码
  3. Reviewer Agent：审核 diff
  4. Executor Agent：跑测试、提 PR

12. 生产化要注意的 8 个坑

  1. 工具参数幻觉：模型经常瞎编路径。工具入口加白名单校验，非法参数直接抛错让它重试。

  2. RAG 命中率低：

    • embedding 模型选对（中文选 text-embedding-v2，代码选 code-search-*）
    • chunk size 按语义切（AST 切代码、标题切 markdown），别按 500 字符硬切
    • 加 rerank：先召回 20 条，用 bge-reranker 重排取 top5

  3. Memory 爆炸：对话长了 token 成本线性增长。上滑动窗口 + 摘要（每 10 轮让 LLM 自己压缩前面历史）。

  4. 敏感信息泄露：Advisor 里加脱敏，AK/SK、密码、手机号调用模型前全部替换成占位符。

  5. 工具权限：用户能调的工具要有 RBAC。@PreAuthorize 或 Advisor 里拦截 functionName 做鉴权。

  6. 限流与熔断：DashScope QPS 有限，给 ChatClient 外层套 Sentinel / Resilience4j。

  7. 可观测性：

    • 接 Micrometer 上报 prompt_tokens / completion_tokens
    • 每次请求存成完整 trace（user → tools → model raw response）便于回放
    • 失败请求自动打到人工审核队列

  8. 幻觉兜底：涉及数据结论，要求模型引用工具返回值，引用不上的话术直接拒答：

    “相关查询未返回结果，我无法回答此问题。”

13. 进阶方向

  • 代码 Agent 专用：接 Tree-sitter 做 AST 分析、接 LSP 做符号跳转
  • 沙箱执行：E2B / Daytona / 本地 Docker 池（见我另一篇 DeepAgents 文章）
  • 持久化工作流：长任务拆成 step，写入数据库，支持断点续跑
  • Human-in-the-loop：危险操作（删库、上线）前插一个人工审批节点

一句话收尾：
研发助手 Agent 不神秘，核心就是 “ChatClient + Tools + RAG + Memory” 的反复组合。Spring AI Alibaba 把这些原语全给你封好了，你只需要专注业务：定义工具、灌数据、编排流程。剩下的 90% 是工程活——脱敏、限流、可观测、权限——和大模型没啥关系。
