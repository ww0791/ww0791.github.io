Spring 面试题整理（详解版）

Created2026-05-07|Updated2026-05-07|面试题
|Word Count:2.8k|Reading Time:10mins|Post Views:

覆盖 IoC / AOP / Bean 生命周期 / 循环依赖 / 事务 / Spring MVC / Spring Boot 高频题。
每题配原理 + 源码关键点 + 面试话术，可直接背。

一、IoC / DI

Q1. 什么是 IoC？什么是 DI？两者关系？

IoC（Inversion of Control，控制反转） 是一种设计思想：对象的创建、依赖的装配不再由使用者 new，而是交给容器完成。程序员只负责”声明”，容器负责”装配”。

DI（Dependency Injection，依赖注入） 是 IoC 的一种实现方式：容器在创建对象时，把它依赖的其他对象”注入”进来。

关系：IoC 是思想，DI 是手段。Spring IoC 容器通过 DI 完成控制反转。

Q2. Spring 有几种依赖注入方式？各自优缺点？

  1. 构造器注入（推荐）

    优点：依赖不可变（final）、强制依赖、便于单测（直接 new）、能暴露循环依赖。

  2. Setter 注入：可选依赖场景。

  3. 字段注入（@Autowired 加字段）：不推荐。隐藏依赖、无法 final、脱离容器无法测试。

话术：Spring 官方文档明确推荐构造器注入，@Autowired 放字段是”开发方便但工程质量差”的做法。

Q3. @Autowired 和 @Resource 区别？

维度 @Autowired @Resource
来源 Spring JSR-250（JDK）
默认按 类型（byType） 名称（byName）
找不到 报错（可用 required=false） 报错
多个匹配 配合 @Qualifier 通过 name 属性

话术：想强调”跟 Spring 解耦”用 @Resource，其他情况用 @Autowired。

Q4. Spring 容器有哪几类？BeanFactory 和 ApplicationContext 区别？

  • BeanFactory：最底层容器接口，懒加载（首次 getBean 才实例化）。
  • ApplicationContext：BeanFactory 的子接口，预加载（启动就实例化所有单例）、支持事件发布、国际化、AOP、资源访问。

日常开发用 ApplicationContext（AnnotationConfigApplicationContext / ClassPathXmlApplicationContext）。

二、Bean 生命周期

Q5. Bean 的完整生命周期？（高频！）

一句话总结：实例化 → 属性注入 → 初始化 → 使用 → 销毁。

展开 11 步：

  1. 实例化：createBeanInstance，调用构造器（此时属性还没注入）
  2. 属性填充：populateBean，完成 @Autowired / @Value 注入
  3. Aware 回调：依次调 BeanNameAware / BeanFactoryAware / ApplicationContextAware 的 setXxx
  4. BeanPostProcessor.postProcessBeforeInitialization 前置增强
  5. @PostConstruct 注解方法
  6. InitializingBean.afterPropertiesSet
  7. 自定义 init-method
  8. BeanPostProcessor.postProcessAfterInitialization 后置增强（AOP 代理就在这里创建！）
  9. Bean 就绪，业务使用
  10. 容器关闭时：@PreDestroy
  11. DisposableBean.destroy() → 自定义 destroy-method

关键点：AOP 代理对象是在步骤 8 生成的，所以循环依赖时需要三级缓存提前暴露早期对象。

Q6. BeanFactoryPostProcessor 和 BeanPostProcessor 区别？

  • BeanFactoryPostProcessor：在所有 Bean 实例化之前执行，可以修改 BeanDefinition（即”Bean 的图纸”）。典型：PropertySourcesPlaceholderConfigurer 解析 ${}。
  • BeanPostProcessor：在每个 Bean 实例化之后、初始化前后执行。典型：AutowiredAnnotationBeanPostProcessor（处理 @Autowired）、AnnotationAwareAspectJAutoProxyCreator（生成 AOP 代理）。

口诀：Factory 改图纸，Bean 改成品。

三、循环依赖（超高频）

Q7. Spring 如何解决循环依赖？三级缓存分别是什么？

场景：A 依赖 B，B 又依赖 A。

三级缓存（在 DefaultSingletonBeanRegistry 里）：

缓存 字段 存什么
一级 singletonObjects 完全初始化好的成品 Bean
二级 earlySingletonObjects 已经代理过、属性未注入完的早期 Bean
三级 singletonFactories ObjectFactory 工厂，调用时返回早期对象（普通对象或 AOP 代理）

解决流程（A 先被创建）：

  1. A 实例化 → 把 A 的 ObjectFactory 放进三级缓存
  2. A 填充属性，发现需要 B → 去创建 B
  3. B 实例化 → 三级缓存也存一份
  4. B 填充属性，需要 A → 查一级 → 查二级 → 查三级 → 命中三级，执行工厂（触发 AOP 判断）返回早期 A，提升到二级缓存，删三级
  5. B 完成初始化，放入一级缓存
  6. A 拿到 B 后完成初始化，放入一级缓存

Q8. 为什么必须三级而不是二级？

核心：AOP 代理需要提前生成时机判断。

如果只有二级缓存，一实例化就要立即判断要不要创建代理对象，所有 Bean 都得在早期判断一次，性能差。

三级缓存的 ObjectFactory 是延迟执行的：只有真的发生循环依赖时才调用工厂，此时才判断”需不需要 AOP 代理”。没有循环依赖的场景，代理仍在生命周期第 8 步（postProcessAfterInitialization）正常生成。

话术：三级缓存是为了在”支持 AOP 代理”和”不发生循环依赖时不提前代理”之间取平衡。

Q9. Spring 能解决哪些循环依赖？哪些不能？

能解决：

  • 单例 + 属性注入/Setter 注入 ✓

不能解决：

  • 构造器注入的循环依赖 ✗（实例化时就互相依赖，连一级缓存都进不去）
  • 原型（prototype）作用域循环依赖 ✗（每次都新建，无法缓存）
  • @Async 等代理 bean 循环 有时会报错（早期对象不是最终代理）

四、AOP

Q10. AOP 的核心概念？

  • 切面（Aspect）：横切关注点的模块化（如日志、事务）。
  • 连接点（Join Point）：程序执行中的一个点（方法调用、异常抛出）。
  • 切点（Pointcut）：匹配连接点的表达式，如 execution(* com.xx.service.*.*(..))。
  • 通知（Advice）：切面要做的事（@Before/@After/@Around/@AfterReturning/@AfterThrowing）。
  • 织入（Weaving）：把切面应用到目标对象的过程。Spring AOP 是运行时动态代理（JDK 或 CGLIB）。

Q11. Spring AOP 和 AspectJ 区别？

维度 Spring AOP AspectJ
织入时机 运行时 编译期 / 类加载期
代理方式 JDK 动态代理 / CGLIB 字节码修改
性能 有代理开销 更快
能力 只能拦截 Spring Bean 的方法 任意方法、字段、构造器
使用难度 简单 需要 aspectj 编译器

Spring AOP 默认用 JDK 代理（接口）；若目标类无接口，自动降级为 CGLIB（继承）。

Q12. AOP 失效的常见场景？

  1. 同类内部方法调用：this.xxx() 不走代理对象 → 切面不生效。

    解决：注入自己 @Autowired A a; a.m2(); 或用 AopContext.currentProxy()。

  2. private / static / final 方法：JDK 代理只能代理接口方法，CGLIB 不能代理 final。

  3. Bean 不由 Spring 管理：new 出来的对象没代理。

五、Spring 事务

Q13. @Transactional 原理？

本质：AOP 环绕通知。由 TransactionInterceptor 在方法前后：

  • 方法前：DataSourceTransactionManager.getTransaction() 开启事务（获取连接、禁用 autoCommit）
  • 方法正常：commit()
  • 方法异常：rollback()

Q14. 事务传播行为有哪 7 种？

传播级别 含义
REQUIRED（默认） 有事务就加入，没有就新建
REQUIRES_NEW 挂起当前事务，新建独立事务
NESTED 嵌套事务（SavePoint），外层回滚内层一起回
SUPPORTS 有就用，没有非事务执行
NOT_SUPPORTED 挂起当前事务，非事务执行
MANDATORY 必须有事务，没有就抛异常
NEVER 必须无事务，有就抛异常

典型考题：记日志用 REQUIRES_NEW（主事务回滚日志也要保留）。

Q15. @Transactional 失效场景？

  1. 同类内部调用（见 Q12）
  2. **方法非 public**（Spring AOP 默认只处理 public）
  3. 异常被 catch 吞掉：事务看不到异常，不会回滚
  4. 抛出的是检查异常（默认只回滚 RuntimeException/Error），需要 rollbackFor = Exception.class
  5. 数据库引擎不支持事务（如 MyISAM）
  6. 多数据源没配对应事务管理器
  7. @Transactional 方法被 final/static 修饰

Q17. @RequestParam / @PathVariable / @RequestBody 区别？

  • @RequestParam：URL 参数 ?id=1 或表单。
  • @PathVariable：REST 风格路径 /user/{id}。
  • @RequestBody：请求体 JSON/XML，配合 HttpMessageConverter（默认 Jackson）反序列化。

七、Spring Boot

Q18. Spring Boot 自动装配原理？

入口：@SpringBootApplication = @Configuration + @EnableAutoConfiguration + @ComponentScan。

关键是 **@EnableAutoConfiguration**：

  1. 通过 @Import(AutoConfigurationImportSelector.class) 导入一个选择器
  2. 选择器调用 SpringFactoriesLoader.loadFactoryNames()，读取 classpath 下所有 jar 的 META-INF/spring.factories（Spring Boot 2.x）或 META-INF/spring/org.springframework.boot.autoconfigure.AutoConfiguration.imports（2.7+/3.x）
  3. 拿到所有自动配置类列表，按 @ConditionalOnXxx 条件筛选后注册到容器

核心 4 条件注解：

  • @ConditionalOnClass：classpath 有某个类才生效
  • @ConditionalOnMissingBean：容器里还没这个 Bean 才生效
  • @ConditionalOnProperty：配置文件里有某个 key 才生效
  • @ConditionalOnWebApplication：只在 Web 项目生效

话术：自动装配 = “约定 + 条件装配 + SPI 加载”。

Q19. Spring Boot Starter 原理？

Starter 本质是个 依赖聚合 + 自动配置类 的 jar：

  1. pom.xml 里 dependencies 列出相关依赖（如 spring-boot-starter-web 包含 web、tomcat、json）
  2. spring.factories / AutoConfiguration.imports 声明自动配置类
  3. 自动配置类读 application.yml 配置项（通过 @ConfigurationProperties），按条件注册 Bean

Q20. Spring Boot 启动流程？

核心 run() 7 步：

  1. new SpringApplication()：推断应用类型（Web/非 Web）、加载 ApplicationContextInitializer / ApplicationListener
  2. 发布 ApplicationStartingEvent
  3. 准备 Environment（加载 application.yml、命令行参数、环境变量）
  4. 打印 banner
  5. 创建 ApplicationContext（Web 项目是 AnnotationConfigServletWebServerApplicationContext）
  6. prepareContext → refresh（真正的 Bean 装配 + 启动内嵌 Tomcat）
  7. 执行 CommandLineRunner / ApplicationRunner

八、其他高频

Q21. Spring 中用到了哪些设计模式？

  • 单例：默认 Bean 作用域（注意是”容器级单例”，不是 JVM 单例）
  • 工厂：BeanFactory / ApplicationContext
  • 代理：AOP（JDK 动态代理、CGLIB）
  • 模板方法：JdbcTemplate / RestTemplate
  • 观察者：ApplicationEvent / ApplicationListener
  • 策略：InstantiationStrategy（不同 Bean 实例化策略）
  • 适配器：HandlerAdapter（不同类型 Controller 统一调用）
  • 责任链：Spring Security 的 Filter 链、MVC 拦截器链

Q22. Spring Bean 作用域有哪几种？

作用域 含义
singleton（默认） 容器内单例
prototype 每次 getBean 新建
request Web 请求级
session Web 会话级
application ServletContext 级
websocket WebSocket 会话级

坑：singleton 注入 prototype，默认只注入一次。解决：@Lookup 方法注入、或注入 ObjectProvider<T> 每次 getObject()。

Q23. @Configuration 和 @Component 区别？

两者都能声明 Bean，但 @Configuration 类会被 CGLIB 增强：

换成 @Component 后，b() 里直接调 a() 会每次都 new，破坏单例。

根因：@Configuration 用 CGLIB 代理类，a() 被拦截从容器取 Bean；@Component 不代理，直接执行方法。

Q24. @ComponentScan 和 @MapperScan 区别？

  • @ComponentScan：扫 @Component / @Service / @Controller / @Repository。
  • @MapperScan（MyBatis）：扫 Mapper 接口，用 MapperFactoryBean 为接口生成代理实现类注册到容器。
